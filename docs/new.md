## 背景

对照游戏 1.98.1 的实际行为后确认，工具的动画蒙皮与游戏存在系统性差异：

- 引擎按 **stick 下标 0–16** 查表，用固定粒子下标（1、2、3、4、5、8、9、10、11、12）构成的"身体参考系"决定每根骨段的 roll，原点取 **a 端粒子**；工具按粒子 id/name 查 lateral 规则、原点取中点、手臂走 bind 相对最短弧。
- 全部 556 个 vanilla 动画上，工具与游戏的骨段旋转差中位数：上臂 33°–56°、前臂 71°–74°、腿 4°–10°、肩颈 8°；常用动画体素最大偏差 4–8 体素（约 14–25 cm）。
- 游戏每帧的姿态是两层合成：`bodyAreaHint=2` 的粒子来自上半身动画并按粒子 8 对齐，且跟随瞄准朝向旋转；其余跟随移动方向。工具目前不体现这一点。
- 现存 bug：1.98.1 的 vanilla `soldier_animations.xml` 含 `<!-- ---- -->` 注释，`animation_io` 解析直接失败。

目标：动画模式下看到的就是游戏里的样子；异形骨作者能在工具里提前发现引擎规则带来的问题。

## 数据语义约定

- **stick 下标 = XML 顺序 = constraintIndex**（已有约定），新增含义：它决定引擎套用哪条朝向规则。
- **粒子下标**（XML 顺序）1、2、3、4、5、8、9、10、11、12 是引擎语义粒子；下标 8 另作上半身层对齐锚点。
- `bodyAreaHint`：1 = 下半身层 / 移动朝向，2 = 上半身层 / 瞄准朝向。其它值引擎按"非 2"处理。
- 引擎复刻只改**动画模式下的体素位置计算**；绑骨数据、XML 读写格式不变。

## 第三轮：左右对称与 bind 错位判定（2026-09-24）

起因：蜘蛛异形骨在引擎蒙皮下左右不对称；引擎视图满屏报红。

### 新查清的事实

1. **只有部分槽位对能严格左右对称**。姿态严格镜像后逐体素比较：腿规则 (0|1 ↔ 3|4)、上臂 (12,10)、
   胸廓 (6,9) 两侧结果严格镜像（方向一致时）；前臂 (13,11) 在胸廓不变形时镜像（见实施结果）；
   (5,8)、(14,15) 两侧用同一规则，FromAxes 不正交时两侧结果不同，改方向也救不回来。
2. 不能只追对称：同一对骨段放进不同槽位，**跟随误差**（渲染出来的骨段方向偏离实际骨段）差别很大，
   前臂槽最好，胸廓槽装腿会崩。代价要同时看 不对称 / 跟随 / 变形 / 静止错位。
3. 原来的 bind 错位阈值是绝对体素数（按 55 体素高的人形定），大模型上误报：蜘蛛 150 体素长的腿偏 4.5
   体素只占 3%。改为"相对误差 + 看得见的下限"。
4. 腿张开到偏离正后方 55° 以上时腿槽规则退化（蜘蛛眩晕动作里第四对腿就是这样坏的）。

### Commit 14：bind 错位改为相对判定，本帧与静止错位分开显示

- `engine_skin`：`frame_grade`（只看本帧 sigma / 变形）、`bind_grade`（相对误差 > 5% 且 ≥ 0.5 体素为注意，
  > 15% 且 ≥ 2 体素为异常），`grade` 取两者较大；`bind_warnings` 按新判定。
- 绑骨工具里的体检 bind 带上体素，才能算出错位体素数；绑定改动计版本号做缓存。
- 引擎视图规则表：「本帧」「整段最差」只按本帧着色，新增「静止错位」列。

### Commit 15：左右对称检查与槽位优化

- `engine_skin`：镜像粒子表、镜像骨段对分类、逐体素镜像比较、槽位指派搜索（代价 = 不对称 ×2 / 跟随 /
  变形取大后取 P95，与静止错位取大；静止错位 > 5 体素的新位置不考虑；改动至少换来 2 体素才做）。
- 结构检查新增"左右不对称"（两个工具都用合成姿态估计；真实动画的数值在绑骨工具的优化窗口里看）。
- 绑骨工具：骨段「对调方向」「与…交换下标」（绑定一起换，可撤销）；「左右对称优化…」窗口：
  可载入动画文件（按名字筛选）评估，后台计算，列出每对骨段的现状 / 建议与代价，一键应用（可撤销）。

### 实施结果（2026-09-24）

Commit 14–15 合成一个提交落地（同几个文件交织，拆开反而看不清）。实测修正了计划里的两点：

- 前臂槽 (13,11) 不是"始终"对称：蜘蛛的真实动作里严格对称，随机姿态下不是——它要求胸廓不变形。
  结构检查用的合成姿态因此改为"胸廓粒子 1、2、3、8 整体刚性转动、其余粒子扰动"，估计值与真实动作吻合
  （大蜘蛛原骨架 #5/#8 估 30 / 实 25，#14/#15 估 8 / 实 6.5）。
- 搜索目标改成"不对称按两倍计"，并把"原样（两侧方向不一致）"也列为候选，否则会为总和最小而牺牲对称。

两只蜘蛛的结果：大蜘蛛加权合计 177 -> 128、8 条腿严格对称（代价：第四对腿跟随 22.6 -> 33、变形 13.7 -> 24）；
小蜘蛛 68 -> 38，各项都不变差。之前手工给的 symfix 实测合计 190、比原样还差，已作废。

验证（临时脚本，不入库）：判定拆分；绑骨面板两种语言；合成姿态与载入合集动画（尺寸自动筛掉另一只蜘蛛、名字筛选）
两种搜索的结果与离线原型逐项一致；应用后与离线生成的模型文件逐项一致，撤销还原；改动后结果判为过期；

绑骨工具走完搜索 / 应用 / 撤销 / 交换 / 对调）全部 0 报错。

  镜像粒子表可能不一一对应 -> 视为不对称；右侧在 +x 的骨架"维持原样"不在候选里 -> 按集合判断；
  动画模式下摆姿态也让绑定版本号 +1 -> 只在绑骨模式计数
- 游戏镜头按钮生效那一帧骨架线用旧矩阵；骨段编辑关闭时仍能应用建议；两处文档表述

另有一条**改变结论的观察**：游戏先按角色朝向把粒子转到世界坐标，再算骨段朝向，bind 却用模型空间。
坐标轴不正交时 FromRotationMatrix 不随旋转协变，蒙皮结果随朝向变化（vanilla 中位 0.05、最大约 14 体素；
蜘蛛可达几十上百体素）。前面"腿槽严格对称"只在默认朝向成立。评估器改为按 0 / 45 / 90 / 135 度四个朝向评估，
对称警告改为相对阈值（> 骨段尺寸 10% 且 >= 2 体素）。重新评估后：
- 大蜘蛛：之前给的修正版合计 288，比原样 248 还差（第四对腿进腿槽后在 45° / 90° 下崩），作废；
  新方案 165：第四对腿留在 5/8（它在各朝向下反而最好），第二对腿进前臂槽，躯干块进腿槽。
  第四对腿的不对称（约 24 体素）在任何槽位都消不掉。
- 小蜘蛛：之前的修正版 61（原样 76.5）仍有效；新方案 58。
- 眩晕：新骨架下原动作已无问题（最坏 17.5 体素）；第四对腿朝后 30° 的版本最坏 16.3、不穿插腹部。

## 第四轮：角色朝向预览（2026-09-24）

用户要求：动画工具加"角色朝向"滑杆和一键回正。

- `EditorState.preview_heading_deg`（-180..180，默认 0）与 `set_preview_heading()`：引擎蒙皮先把显示姿态
  （含合成预览）按朝向转到世界坐标再算，结果再转回来显示——模型在视口里原地不动，只看随朝向变化的差异；
  体素立方体朝向同样转回。
- 本帧体检、整段扫描、视口高亮都按当前朝向算；扫描签名带上朝向，改朝向后提示重扫。
- 动画面板「蒙皮规则」下方：朝向滑杆 + 「回正」按钮；旧版规则与朝向无关，选旧版时注明。
- 朝向不为 0 时状态栏显示当前朝向。
